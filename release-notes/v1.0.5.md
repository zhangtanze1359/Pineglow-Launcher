## 修复

- **替换脚本不再依赖 PATH 与进程名长度**：替换脚本过去直接调用系统的 `find` / `tasklist` / `ping` / `fc`，
  这几个命令在 PATH 里被别的程序抢先时（例如装了 Git 并把它加到 PATH 前面），
  「等待启动器退出」的判断会失效——脚本以为启动器已经退出，实际还在运行，替换被文件占用挡回来。
  另外 `tasklist` 的默认表格输出会把进程名截到 25 个字符，而发行文件名
  `Pineglow-Launcher-win-x64-single-file.exe` 有 31 个字符，旧脚本因此永远看不到「自己还在运行」。
  本版把四个系统命令改成绝对路径，并把进程查询改成不截断的 CSV 格式。
  你原有的下载源、双源回退、大小与 SHA256 校验、替换前的备份与失败回滚全部保留。
- **同一时刻只会发生一次替换**：过去两个几乎同时到达的「立即重启更新」请求都能通过检查，
  各自写一份替换脚本并拉起进程，两份脚本会同时覆盖同一个启动器文件。
  本版把「检查 + 认领」合成一步原子操作，认领发生在文件校验与启动脚本之前；
  已经开始替换后，重复请求只回去同一状态，界面也把按钮置为不可点。
- **下载与替换互斥**：替换已经开始时，新的下载请求会被拒绝，不会改掉正在使用的更新包。
- **界面上能看到「正在替换」，失败后能当场重试，成功后有确认**：过去点完「立即重启更新」界面停在「更新包已下载」，
  用户不知道替换是否已经开始；下载或替换失败只有一行红字，没有重试入口；
  上次真的换成了新版也完全不提示。本版补上这些状态，且下载失败时当场给出「重试下载」。

## 版本

- 版本号统一为 **1.0.5**（程序集版本与发布标签一致）。

## 升级覆盖范围

- **从 v1.0.4 的在线自动升级不能保证成功**。v1.0.4 自带的替换脚本在它的发布形态下
  （发行文件名 + 默认进程查询格式）会判定「启动器已退出」，随后替换被文件占用挡回，界面会显示
  「上次替换未成功（replace_failed）」，重新打开仍是旧版本。
  这一点已用官方 v1.0.4 二进制实测复现，且**不在 v1.0.5 能修复的范围内**——那段脚本是 v1.0.4 自己生成的。
- **从 v1.0.5 起**，在线自动升级（检查 → 下载 → 校验 → 确认 → 替换 → 自动重启）可用。

### v1.0.4 用户：请手动升级一次

三步，数据不用动：

1. **完全退出**正在运行的 v1.0.4（关掉启动器窗口，确认任务管理器里没有
   `Pineglow-Launcher-win-x64-single-file.exe`）。
2. 下载本页的 `Pineglow-Launcher-win-x64-single-file.exe`，用它**覆盖**原来那个同名文件
   （放在同一个目录，文件名保持一致）。实例、账户、游戏文件都在原有的数据目录里，覆盖可执行文件不会动它们。
3. 重新打开启动器，设置 → 更新 里的「当前版本」应显示 **1.0.5**。

之后的新版本会通过启动器自己的「检查更新」正常升级，不需要再手动替换。

## 更新方式

下载本页的 `Pineglow-Launcher-win-x64-single-file.exe`，放入可写目录后运行；v1.0.5 及之后的版本
可直接通过启动器检查更新。
