## 新增

- **Mod 批量更新**：Mod 抽屉里可以一次性检查所有已安装 Mod 的更新，并逐项应用。
  每一项单独提交、单独显示进度，**某一项失败就停在那一项**，不再继续后面的项，避免一次更新把整排 Mod 弄成半新半旧。
  更新途中可以取消——取消只停后续项，已经成功的项不回退；对已成功的项也可以逐项撤销。
- **游戏退出后自动备份**：可以为每个实例单独打开「退出游戏时自动备份存档」。
  开关是实例级的，不是全局；判定与执行分离，**只备份非空的存档**（`SizeBytes > 0`），空存档会被明确跳过而不是产出一个 0 字节的假备份。
  v1.0.5 及更早的版本没有这个能力——旧版在二分排查流程里明确提示「启动器不会自动备份或复制你的存档，请自行备份」。
- **启动检查给出结构化引导**：启动失败时不再只给一行错误，而是按原因给出可执行的下一步。
- **存档删除可恢复**：删除存档会留下可恢复记录，在恢复区里可以还原或彻底清除。

## 修复

- **存档恢复区一直 404**：前端请求 `/saves/recoveries` 时，路由层把段数多算了 1，导致该页面一直打不开。
  本版修正路由段数匹配，恢复区可以正常列出与操作。
- **图标「失败后可重试」约 40% 概率失效**：图标加载的 in-flight 表在任务完成后没有清干净已完成的条目，
  导致失败后重试时可能拿不到新任务。本版修正清理时机。
- **旧 mcbbs 下载源迁移**：`downloadSource` 的旧取值会被规范化并写回，避免用户在设置里看到的与实际使用的不一致。
  迁移只写 `config.json`，**不触碰 SecretStore**——凭据读取失败时不会误删无关凭据。
- **缺少 CurseForge Key 时给出可执行的引导**：不再只是报错，而是区分「未配置」与「端点被拒」两种情况，各自给出下一步。
  同时移除了早期版本内嵌的 API Key，改为运行期配置或环境变量。

## 已知限制

- **仅支持 Windows x64**。本版本为 win-x64 单文件。CI 的三平台矩阵不等于三平台可交付。
- **从 v1.0.4 的在线自动升级不能保证成功**（沿用 v1.0.5 的说明）：v1.0.4 自带的替换脚本在它的发布形态下会判定「启动器已退出」，
  替换随后被文件占用挡回，界面显示「上次替换未成功」。这段脚本是 v1.0.4 自己生成的，**不在本版能修复的范围内**。
- **从 v1.0.5 起**，在线自动升级（检查 → 下载 → 校验 → 确认 → 替换 → 自动重启）可用。

## 更新方式

从 v1.0.5 升级：直接使用启动器内的「检查更新」即可，不需要手动替换。

从更早版本升级：请先手动覆盖一次可执行文件到 **v1.0.5**，再从 v1.0.5 走在线升级；或直接手动覆盖到本版本。
实例、账户、游戏文件都在原有的数据目录里，覆盖可执行文件不会动它们。

下载本页的 `Pineglow-Launcher-win-x64-single-file.exe`，放入可写目录后运行。
