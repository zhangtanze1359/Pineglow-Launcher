## 本轮想查什么

上一轮确认了缺陷 12 的"僵尸"仍在。但**机制**没说清：
B 监听失败、又没有自己的 API —— 那它的窗口显示的是什么？
我的假设是：**B 的窗口指向 `http://127.0.0.1:48123/`，也就是 A 的 API**（这正是缺陷 12 的原话"静默借用对方 API"）。

**测法**：数每个进程下的 `msedgewebview2.exe` 子进程 —— 有子进程就说明它在渲染。

## 结果：**这个测法不成立**

```
A pid=32672  alive=True   webview children = 1     ← A 在渲染
B pid=21712  alive=True   webview children = 0     ← ？
```

**我本来要据此说"B 根本没有窗口"** —— 但停了一下，发现**这个推论不可靠**：

**WebView2 的浏览器进程是"每用户数据目录共享"的** ——
第二个实例**很可能复用了第一个实例已经拉起的 `msedgewebview2.exe`**，
于是"B 名下 0 个子进程"**完全可能只是"B 借用了 A 的渲染进程"**，
**而不等于"B 没有窗口"**。

**所以这条读数不能支撑任何结论。** 我**不把它写成结论**。

## 那这一轮**确实**确认了什么（这些是可以下结论的）

| 断言 | 证据 |
| --- | --- |
| B 监听失败、**日志里有完整调用栈** | 上一轮 |
| **B 不退出** | `B alive = True`（两轮都是） |
| **A 死后 B 仍活着** | `B alive = True`（A 已被杀） |
| **此时默认端口无人服务** | `port serving = False` |
| **B 是一个活着但不提供任何服务的进程** | 以上四条合起来 |

**最后一条不依赖窗口的形态** —— 无论 B 有没有窗口，它**都不提供 API、也不退出**。
**这足以支撑"僵尸"这个判断**，也足以支撑那个取舍。

**不能下结论的**：B 到底有没有窗口、窗口里显示什么。
**要查清它，得换一个不依赖"子进程归属"的手段**（例如截 B 的窗口，或查 B 是否请求过 A 的 API）。
