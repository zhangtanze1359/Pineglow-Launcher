# 记录 64：新缺陷 **#15 —— 实例目录缺失时「自检」报一切正常，而启动 500 且不留日志**

运行标识：`run-2026-10-10_015215-578dbafb` ｜ 2026-10-11 22:44–22:52（+08:00）
性质：**只读审计 + 隔离夹具实测，产品目录零改动**（0 staged）。

---

## 问的是哪个没问过的问题

上一轮问的是「**配置文件**坏了会怎样」。本轮问「**实例目录**没了会怎样」——
用户手动删过、磁盘清理工具删过、外接盘拔了，都会造成这个状态。
而产品**自带一个 `prelaunch-check`**，存在的意义正是"启动前告诉用户哪里不对"。

## 实测

夹具：一份真实配置，把 `d7-fabric 导入` 的 `GameDirectory` 指向一个**不存在**的路径。

| 观测 | 读数 |
| --- | --- |
| 目标目录存在吗 | **False**（已确认） |
| API 起来了吗 | **apiUp = True** ✓ |
| 实例还在列表里吗 | **True** |
| **`prelaunch-check`** | **ok=True，errors=0，warnings=0** ← **一切正常？** |
| **`launch`** | **HTTP 500（内部服务器错误）** |
| 产品日志 | **只有 2 行**（启动 + 监听）——**那次 500 一个字都没留下** |

## 两个问题

### ① `prelaunch-check` 给了**假阴性**

实例目录**不存在**，自检却报 `ok=True / 0 错误 / 0 警告`。
这是**用户用来诊断启动失败的那个界面**——它说"没问题"，然后启动就 500。
**它比不给信息更糟**：用户会以为问题在别处。

### ② 500 没有日志

与缺陷 10（启动失败无日志）、缺陷 14（配置损坏无日志）**同一族**：
**失败发生了，但日志里查不到。**

## 定性：缺陷 **#15**

| 维度 | 判断 |
| --- | --- |
| 严重度 | **中**：不丢数据，但**诊断界面给假阴性**，且失败无日志 |
| 触发条件 | 实例目录被删/移动/所在盘不可用 |
| 修复方向 | ① `prelaunch-check` 增加"实例目录是否存在/可写"这一项，缺失时**报错而不是通过**；② launch 的异常路径补日志（与缺陷 10/14 同一处改法） |

## 一个正在成形的模式

**缺陷 10、14、15 是同一族：失败被静默吞掉或没有留下任何可查记录。**

- 10：启动失败 → 进程消失、无日志
- 14：配置损坏 → 静默换成默认值、无日志
- 15：实例目录缺失 → 自检报通过、启动 500 无日志

**三条都不是"功能没做"，而是"失败了但不说"。** 这类问题在开发机上很难被发现
（开发机的目录总是齐的、配置总是好的），但**在用户的机器上恰恰是最常见的状态**。
报告里可以把这三条并成一族看待——修法也是同一个（**在失败路径上写日志，并让自检说实话**）。
