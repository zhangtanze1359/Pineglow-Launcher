### 与前面几个视图的本质区别：状态所有权

`contentPageGen` 与 `contentDebTimer` 的**唯一写者是 `goTo`（导航核心）**：

- 进入 content 时 `goTo` 把 `contentPageGen` 设为本次 `navSeq`
- 切走 content 时把它设为 `-1`，并 `clearTimeout(contentDebTimer)`
- `renderContent` / `contentRerenderGrid` / `retryLoadStateAndRefresh` 用它们做代际校验

**所以这两个状态没有搬进 `content.js`，而是留在 `launcher.js`。** 若搬走，`goTo` 就得反向
依赖视图模块的内部变量——导航核心 ← 视图模块的反向依赖，是错误的耦合方向。

`content.js` 通过注入的**访问器**读写它们：

```js
SG.content.__wire({
  toast, getState: () => STATE, loadState,
  selectedInstanceId: () => selectedInstanceId,
  stateLoadFailedLast: () => stateLoadFailedLast,
  pageGen: () => contentPageGen,              // 只读
  setDebounce: (fn, ms) => {                  // 句柄仍写入 launcher 的 contentDebTimer
    if (contentDebTimer !== null) { clearTimeout(contentDebTimer); contentDebTimer = null; }
    contentDebTimer = setTimeout(fn, ms);
  },
  uiIcon, uiSearch,                           // 见下：不复刻，直接注入原实现
});
```

`STATE` / `selectedInstanceId` / `stateLoadFailedLast` 同样传取值函数而非快照——它们会被
`loadState` 整体替换。

`uiIcon` / `uiSearch` 采**注入**而不是在 `content.js` 里复刻：launcher 里有一张 13 项图标
总表，复刻一份就多一个漂移点（见第五节，我确实在这上面栽过一次）。

## 四、过程中的三次自造缺陷（全部当场发现并修好）

写在这里不是自我批评，而是因为**它们正是"全绿不等于对"的实例**。

### 4.1 凭印象复刻 `contentErrorBlockHtml`，写成简化版

第一版我手写了一个 `<span class="content-error-msg">…<button class="mod-install" …>` 的
简化错误块。真实版本是 `.state-icon` + `.state-title/desc` + `details/pre` 技术错误折叠 +
`class="content-retry-btn"`。`current-version-errors.test.cjs` 的 CV-06 立刻红。

**教训**：拆视图时"看起来差不多"的复刻就是行为偏差。改为用原文逐字替换，并把源码比对
（第二节 A）作为常规验证手段，而不是靠测试兜底。

### 4.2 `STATE` 取成局部快照，破坏 `await loadState()` 之后的取值

第一版 `renderContent` 开头写了 `const STATE = _getState();`。原版用的是**全局 STATE**，
`await loadState()` 返回后全局已被整体替换；快照会让后续读取拿到**加载前的空值**——即
"直进资源页时永远看不到实例过滤提示"。

同一处错误在 `searchContentOptions` / `retryLoadStateAndRefresh` 也各有一份。三处全部改成
每次调用 `_getState()`。

**这是源码比对直接抓出来的**（`searchContentOptions` 第 2 行差异），不是测试抓到的——
现有测试没有覆盖"直进 content 页"这条路径。

### 4.3 对比脚本的字段名写错，导致"全绿但什么都没测"

渲染对比第一版，mock 返回 `{ items: [...] }`，而 `api.js` 读的是 `data.results`。
10 个场景全部"逐字符一致"，但所有输出长度都是 1262 字符——**搜索结果一张卡片都没渲染**，
那个场景实际只测了空列表。

发现方式：看长度可疑（所有场景都在 1262±3），去查 `api.js` 的字段名。修正为 `results`
后「有结果」场景从 1262 涨到 3113，且仍然逐字符一致。

随后补了**哨兵断言**（声称有结果的必须出现 `.mod-card`，声称失败的必须出现 `.content-error`），
让这类"空转对比"以后会直接红。

## 五、守卫变动与变异验证

`ui-script-order.test.cjs` 从 9 条增至 **10 条**，新增：

> 每个拆出模块用到的注入项，launcher.js 的 `__wire` 里都必须真的提供

由来：**MUT-D 暴露的真实盲区**。

| 变异 | 操作 | 结果 |
|---|---|---|
| MUT-A | 从 `SCRIPT_ORDER` 删 `js/content.js` | **红** 3 条 |
| MUT-B | 从 `index.html` 删 `<script src="js/content.js">` | **红** 2 条 |
| MUT-C | `renderContent()` 掏空为 `return ''` | **红** 1 条 |
| MUT-E | 从 `__wire` 删 `pageGen: () => contentPageGen` | **全量红 1 条**（行为测试能抓） |
| MUT-D | 从 `__wire` 删 `setDebounce` | **全量 485 全绿，什么都没抓到** |

MUT-D 是既有覆盖缺口：content 的搜索框 debounce **没有任何行为测试**（拆分前就没有）。
删掉注入后 debounce 变成空操作，页面照样渲染、测试照样绿。新增的注入面守卫补上了这条
（改后 MUT-D / MUT-E 均能在静态层直接红）：

```
✖ SG.content.__wire 缺少注入项 "setDebounce"（content.js 读 deps.setDebounce）：该功能会静默失效
✖ SG.content.__wire 缺少注入项 "pageGen"（content.js 读 deps.pageGen）：该功能会静默失效
```

需要说明的边界：这条守卫只保证**注入项不缺失**，不保证注入的行为正确。debounce 的
**实际行为**仍然无测试覆盖，本轮不新增行为测试（那属于补测，应由裁判方立项）。

另：MUT-A 第一次因锚点用 `\n` 而工作区是 CRLF 导致未注入，改 `\r?\n` 后才有效——与
skins 那次同一类失误，已固定为模式。

`launcher-content.test.cjs` 与 `content-icon.test.cjs` 的拼接顺序是 **content.js 在前**：
`extractFunctionBody` 用 `indexOf` 取首次出现，若 launcher 的薄委托在前，取到的就是
三行委托而不是实现。这一点在文件里留了注释。

这两份文件里**唯一**放宽的正则是 `installContent` 的参数断言：
`instanceId: selectedInstanceId` → `instanceId: (?:selectedInstanceId|_selectedInstanceId())`。
原因是拆分后实例 id 经注入取值函数访问，语义完全相同；仍然**硬断言必须显式传 instanceId**，
不允许退化成不传或全局猜测。
