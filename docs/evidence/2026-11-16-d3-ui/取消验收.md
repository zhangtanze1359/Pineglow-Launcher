## 这一轮在真机上抓到的三个缺陷（都已修）

1. **下载在最慢的地方不可取消**：旧实现把全部下载塞在 `POST /batch-update` 里、任务创建之前，
   所以"取消"对最耗时的下载阶段完全无效。→ 下载移进 `BatchUpdateRunner`，逐项进行。
2. **计数口径错**：`已应用 N 个` 用的是"非 pending 数量"，把 skipped 也算进去了
   （真机第一次跑出 **已取消，已应用 3 个**，实际只应用了 1 个）。→ 改成只数 `applied`。
3. **阻塞式下载会卡死批次**：`downloadBytes(...).GetAwaiter().GetResult()` 在批次线程里导致
   `state` 永远停在 `cancelling`。→ 改成 `await ... .ConfigureAwait(false)`，真机复验通过。

另外修了一个测试自身的问题：取消用例原本借用 `ModReplacementService.BeforeCommitForTest` 这个
**全局静态钩子**，与并行执行的 `FinalAcceptanceRegressionTests` 互相干扰，全量跑出现过 2 条偶发红。
改成"在下载委托里立取消旗标"，不碰任何全局状态；随后**连跑两遍全量**，均 1410 通过 / 0 失败。
