## 二、执行者这次自己推翻了自己的判断，我复核了

上一轮我在 `open-items.md` 写了 OPEN-06「异步完成路径没有用例覆盖」。
执行者这一轮说那是误判，并给了理由。我独立验证：

```
# 把 RemoveIfSame 改成空方法（模拟注销根本没生效）
$ dotnet test ... --filter FullyQualifiedName~GetAsync_InFlightEntrySurvives
  Expected: 0
  Actual:   1
  失败! - 失败: 1，通过: 0
```

**执行者的更正成立。** 那条用例的 fetcher 是 `async` 且 `await` 一个 TCS，
建任务那一刻 `IsCompleted == false`，走的正是进表 + `ContinueWith` 那条路。

但执行者同时指出「仍然有真实空洞，只是位置不同」，这一点我也验证成立：

- `FailedFetchAllowsRetry` 走同步分支（`Task.FromResult`，根本不进表）
- `InFlightEntrySurvives` 进了表，但验完用 `WaitForConditionAsync` **轮询**等注销——
  轮询会把「注销迟了」这件事洗白

所以新用例的定位是准确的：**不轮询、await 返回后立刻查表**。
