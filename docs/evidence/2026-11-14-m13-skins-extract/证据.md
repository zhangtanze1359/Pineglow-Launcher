## 一、做了什么

把 `ui/js/launcher.js` 里的 Skins 视图拆成**两个**文件，而不是一个：

| 新文件 | 行数 | 内容 |
|---|---|---|
| `ui/js/skin-visuals.js` | 86 | 5 个纯视觉 helper：`steveSvg` / `skinAvatar` / `skinThumb` / `skinFace` / `faceThumb` |
| `ui/js/skins.js` | 257 | 视图本体：`renderSkins` / `bindSkins` / `activeSkinViewer` 生命周期 / `pendingSkin` |

`launcher.js`：**4146 → 3945 行**（净减 201）。

### 为什么拆两层，而不是全塞进 skins.js

这是本步唯一需要**明确决定**的地方（downloads 没有这个问题）：

| helper | 谁在用 | 归属判断 |
|---|---|---|
| `faceThumb` | **设置页** `renderAccountCards`(:315)、**侧栏** `refreshSidebarAccount`(:3826)、skins | 跨视图共享 → 独立层 |
| `steveSvg` / `skinAvatar` | 生产路径无人调用，仅 `SG.__test__` 导出供测试直测 | 共享层 |
| `skinThumb` | 仅 skins 的皮肤卡片 | 依赖共享层 |
| `skinFace` | 仅 `faceThumb` 内部 | 依赖共享层 |

如果硬塞进 `skins.js`，设置页与侧栏就会依赖"皮肤视图模块"来画账户头像——方向是错的。
所以共享视觉层单独成文件，`skins.js` 依赖它。

### `activeSkinViewer` 的所有权（本步的第二个决定）

拆分前三处碰它：`goTo` 切走、`invalidate('skins')`、`bindSkins` 内重建。
前两处是"外部要求销毁该实例"。处理方式：

- 变量本身**移入 `skins.js`**，launcher.js 不再持有该变量（`let activeSkinViewer` 已删除）；
- `skins.js` 导出 `dispose()`；
- launcher.js 侧两处改为 `SG.skins.dispose()`。

这样实例生命周期只有一个所有者，不会出现两份真相。

### 注入面（`SG.skins.__wire`）

```js
SG.skins.__wire({
  toast,
  currentView: () => currentView,
  accounts: () => ACCOUNTS,     // 取值函数：loadAccounts 会整体替换 ACCOUNTS，不能传数组引用
  loadAccounts,
  invalidate,
  goTo,
});
```

比 news/downloads 多三项（accounts / loadAccounts / invalidate / goTo），因为应用皮肤后
需要`上传 → 重新拉账户 → 失效页面 → 重新导航`这一整条链路。

## 四、守卫断言有效性（变异验证）

`ui-script-order.test.cjs` 本次从 8 条增至 **9 条**，新增的是「跨视图共享层也导出了
SG.<模块名>，且被真实使用」。逐个变异验证：

| 变异 | 操作 | 结果 |
|---|---|---|
| MUT-A | 从 `SCRIPT_ORDER` 删 `js/skin-visuals.js` | **红**：3 条失败（清单↔HTML 一致性 / js/ 反向登记 / ⑤-①） |
| MUT-B | 从 `ui/index.html` 删 `<script src="js/skins.js">` | **红**：2 条失败 |
| MUT-C | `renderSkins()` 掏空为 `return ''`（`__wire` 保留） | **红**：1 条失败（渲染入口未委托） |

全部变异在同一 shell 调用内用备份恢复，恢复后 9/9 绿。

> 两处踩坑如实记录：
> 1. 首次 MUT-A 锚点用了 `\n`，而工作区文件是 **CRLF**，导致变异没注入、误以为"守卫没咬住"。
>    改用 `\r?\n` 后才真正验证。（MUT-B/C 未受影响，因为它们用 `patch()` 精确子串匹配。）
> 2. 首次跑守卫时 `NS_ASSIGN` 按文件名推导命名空间，在 `skin-visuals.js`（`SG.skinVisuals`，
>    连字符在 JS 标识符里非法）与 `skins.js`（用 `SG_NS` 别名）上假红。
>    改为显式映射 `NS = { 'skin-visuals': 'skinVisuals', ... }` + 别名白名单。

## 五、过程中的一次自造 bug（已修）

批量给 11 个测试夹具插入加载语句时，`ai-diagnose.test.cjs` 有**两个**运行点，
脚本只匹配了缩进一致的那一个；随后我用 `replace_all` 补第二处，结果把**已插入过的
那一处又插了一遍**，出现重复的 `SKINVIS_JS` / `SKINS_JS` 两行。已立即删除重复行。
最终 485/485 全绿证明重复已清干净（重复加载会让 `SG.skins` 被重新赋值，虽不致命但属于脏改）。
