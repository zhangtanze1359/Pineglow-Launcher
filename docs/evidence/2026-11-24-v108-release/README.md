**与 v1.0.7 的失败不同**：

### 手工补齐（本地网络 46 秒传完）

- 附件上传 → HTTP 201（46 s，53,482,977 bytes）
- `update.json` PUT → HTTP 200
- 端到端：主源 `version=1.0.8`、`sha256=5cb81f53…`、Gitee 直链 200 完整下载

### 结论：runner 出口到 Gitee 的带宽是镜像的真正瓶颈

51 MB 包在 GitHub runner 上 2×5 分钟传不完，本地 46 秒。
**后续发版大概率仍需手工补附件**——镜像的「清单备份/恢复」机制正常，
但大附件上传在 runner 侧不可依赖。
