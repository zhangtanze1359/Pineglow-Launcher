### 拆分范围

| 内容 | 处理 |
|---|---|
| `renderSettings`（141 行） | → settings.js |
| `AUTH_PRESETS` / `sourceLabel` / `openSourcePicker` | → settings.js |
| `bindSettings`（357 行） | → settings.js |
| `aiActiveName` / `renderAccountCards` | → settings.js（**原以为它们被别处用，实测只被设置页用**） |

「更新区」（`updateMonitor` / `renderUpdateTrust` / `initUpdateSection` /
`pollUpdateProgress` / `addUpdateBindings` / `wireWindowControls` / `refreshSidebarAccount` /
`wireNav`）是独立子系统，被 `init` 与全局 UI 使用，不属于设置页私有。settings.js 通过
`__wire` 拿到 `addUpdateBindings` 与 `refreshSidebarAccount` 两个入口。

### 与前面几个视图的对比

| | content | settings |
|---|---|---|
| 导航级状态 | `contentPageGen` **留在 launcher**（goTo 是唯一写者） | 无 |
| 状态归属 | 部分留、部分走 | 全部是 `STATE.config` 的属性 |
| 注入形态 | `pageGen()` 只读 + `setDebounce()` | `getState()` 取值函数，读写都走它 |

settings 的写入依赖**对象引用**：`_getState().config.x = v` 与 `STATE.config.x = v`
作用于同一个对象，所以写入不需要 setter。

### 注入面（18 类改写，可审计）

## 四、过程中的四次自造缺陷（全部当场发现）

**这一节的共同教训：源码比对与渲染比对是两把不同的尺子，缺一不可。**

### 4.1 注释里写了 `*/`，提前闭合块注释

我在文件头的说明里引用了 `/* ---- Settings 更新区 ---- */` 这段代码片段，
其中的 `*/` **提前结束了整个块注释**，导致后面 400 行被当成代码。

症状极具误导性：`node --check` 报错指向第 86 行一个完全合法的模板字符串
（`<div class="modal-title">` 的 `class`），因为解析器早已迷失。

排查花了很久——我一度怀疑编码、BOM、反引号配对、括号配平，全都不对。
最终靠「按行统计 `/*` 与 `*/` 的位置」定位。**修法**：把片段里的 `*/` 写成 `* /`。

### 4.2 只把 `uiIcon` 加进注入清单，忘了替换正文调用

`renderSettings` 里 `_uiIcon('folder')` 之前是 `uiIcon('folder')`——生成脚本的替换表里
没有 `uiIcon`，因为我以为它只在 wire 声明里出现。于是渲染时抛
`ReferenceError: uiIcon is not defined`。

**这个缺陷源码比对抓不到**：归一化会把 `_uiIcon` 还原成 `uiIcon`，两边一致。
是**渲染比对**（11 个场景全红，差异在 `btnOpenLogs` 的 SVG 缺失）抓出来的。

### 4.3 `_uiIcon` 漏进 `wire` 函数 + 声明位置触发 TDZ

补了正文替换后，`wire` 里仍然没有 `uiIcon` 这一项，于是 `_uiIcon` 永远是初始的
`() => ''`——**渲染不报错，只是图标静默消失**。

更糟的是我最初把 `let _uiIcon = () => '';` 声明在 `wire` **之后**，补上 wire 后会触发
TDZ（`Cannot access '_uiIcon' before initialization`）。已前移到注入区。

这一条被**变异 MUT-D** 验证过：从 `__wire` 删掉 `uiIcon`，新增的注入面守卫直接红：
```
✖ SG.settings.__wire 缺少注入项 "uiIcon"（settings.js 读 deps.uiIcon）：该功能会静默失效
```

### 4.4 `aiActiveName` / `renderAccountCards` 漏搬

`renderSettings` 用了这两个 helper，但它们定义在 launcher 的别处（不在我最初划定的
settings 区块里）。运行时抛 `ReferenceError: aiActiveName is not defined`。

我先用手工 grep 找残留标识符，噪音太大（把字符串内容、属性名全算了进来）。
改用「抽取所有 `${...}` 模板表达式里的裸标识符」才定位到。

`renderAccountCards` 还依赖 `faceThumb`，搬到 settings.js 后改为
`SG.skinVisuals.faceThumb(...)`（视觉层已在 skins 那步拆好）。
