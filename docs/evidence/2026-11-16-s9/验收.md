## 六、去掉内置 Key 之后，模组还怎么下？（用户问的那个问题）

**结论：Modrinth 完全不受影响；CurseForge 需要用户自己的 Key（免费申请），缺 Key 时给可执行的引导。**

| 能力 | 需要 Key 吗 | 去掉内置 Key 后的行为 |
|---|---|---|
| Modrinth 搜索 / 版本列表 / 下载 / `.mrpack` 导入 | **不需要** | 不变（公共 API，无鉴权） |
| CurseForge 搜索 / 版本列表 | **需要**（CurseForge API 强制） | 返回 **400 + `code: curseforge_key_required`**，界面提示「在设置页填写 Key，或切回 Modrinth」 |
| CurseForge 整合包导入 | 取决于包内是否含明确 fileId | 已知 fileId 时可直接走 CDN 直链；**项目→文件 的发现仍需要 Key** |
| 已装 Mod 的更新检查 | Modrinth 不需要；CurseForge 需要 | 同上，逐条跳过而不是整批失败 |

**为什么不是"塞回一个 Key 就完事"**：

1. S9 的验收项就是「第三方 Key 不进分发程序」——把它重新内嵌等于把验收当摆设；
2. 那个 Key 已经在 git 历史里泄露过一次，**正确处置是吊销/轮换**，而不是继续依赖它；
3. 分发形态是单文件 exe，任何"随包携带的配置"最终都等于内嵌，绕不开这条。

**界面表现（不是 500，也不是静默空列表）**：

- 后端：新增 `CurseForgeKeyRequiredException`；HTTP 层与内容搜索处理器都把它映射成
  **400 + `{"ok":false,"code":"curseforge_key_required","error":"…请在设置页填写，或设置环境变量 …"}`**。
- 前端：`ui/js/content.js` 读到这个 `code` 时显示 `content.cfKeyRequired`
  （「CurseForge 需要你自己的 API Key（免费申请）：请在设置页填写，或把来源切回 Modrinth —— Modrinth 不需要任何 Key。」）。

**测试（新增 `CurseForgeKeyRequiredTests`，2 条）**

| 用例 | 断言 |
|---|---|
| `CurseForgeSearch_WithoutKey_Returns400WithStableCode` | 无 Key + 无环境变量 → **400**、`code=curseforge_key_required`、错误文案含「设置页」 |
| `ModrinthSearch_DoesNotNeedAnyKey` | Modrinth 搜索**不得**返回 400/该 code（上游 502 也算通过——这条不依赖网络成功） |

**顺带修掉的一个既有隐患**：`LocalApiTestHarness` 有"同一进程只能跑一个 LocalApiService"的全局约束，
但新加的 harness 测试类没有加入 `[Collection("LocalApiService")]` 串行集合，
与 S8 的 `DiagnoseWithoutAiTests` 并行时直接抛「LocalApiService 已在运行」。
三个新类都已并入该集合；**全量连跑两遍：1418 通过 / 0 失败 / 0 跳过**。

## 七、决策变更（2026-11-16 20:36）：本版本不轮换，改为**有截止日期的临时豁免**

编排方决定：**当前还没有真实用户，本版本不吊销/轮换那把 Key，下个版本（`v1.0.5`）再轮换。**

这意味着上一节"移除内嵌 Key"的落地方式要调整——但不代表把验收当摆设，改为**可检查的豁免**：

| 项 | 现状 |
|---|---|
| Key 放在哪 | **只允许** `dev/PineglowLauncher/Pineglow.Launcher.Services/CurseForgeKeyDefaults.cs` 一个文件 |
| 是否有截止日期 | 文件里有 `RemovalDeadline = "v1.0.5"`，守卫测试断言这个标记存在 |
| 解析顺序 | 调用方传入（设置页/配置） → 环境变量 `PINEGLOW_CURSEFORGE_API_KEY` → 内置回退 |
| 其他文件出现字面量 | `SecretHygieneTests.KeyLiteral_AppearsOnlyInTheExemptFile` **直接红** |
| 缺 Key 的引导链路 | 仍保留（`CurseForgeKeyRequiredException` → 400 + `curseforge_key_required`），测试用测试缝把回退关掉来验证 |

也就是说：**本版本用户开箱即用 CurseForge**；下个版本删掉那个文件时，守卫测试会立刻提醒，不会"忘了删"。

**下个版本要做的三件事**（写进文件头，避免口口相传丢失）：
1. 去 CurseForge 后台吊销这把 Key 并换新；
2. 删除 `CurseForgeKeyDefaults.cs`；
3. 全量改走"用户自带 Key / 环境变量"（解析逻辑已支持，删掉回退即可）。

**门槛（本轮改完复跑）**：C# **1418 通过 / 0 失败 / 0 跳过（连跑两遍）**；inventory / css-tokens / closure 全 exit 0。
