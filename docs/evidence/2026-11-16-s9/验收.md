## 三、本轮真正修的：内嵌的 CurseForge Key（违反 S9 验收项）

**修前**：`ModContentService.cs:26` 有一个 **60 字符的 CurseForge API Key 字面量**，
`RequireCurseForgeApiKey` 在用户没配 Key 时**回退到它**。也就是说「第三方 Key 不进分发程序」这条验收，
文档里写着、代码里违反着，而且没有任何测试能发现。

**修后**（`ModContentService`）：

- 常量已删除（源码树里 `$2a$10$` 前缀的字面量为 **0**）；
- Key 只来自 **调用方传入（设置页/配置） → 环境变量 `PINEGLOW_CURSEFORGE_API_KEY`**；
- 两者都没有时抛 `MissingKeyMessage`：**「CurseForge 需要 API Key：请在设置页填写，或设置环境变量 PINEGLOW_CURSEFORGE_API_KEY。」**

**机器守卫**（`SecretHygieneTests`，4 条）：

| 用例 | 作用 |
|---|---|
| `SourceTree_HasNoCurseForgeApiKeyLiteral` | 扫源码树，出现 `$2a$10$` 即红 |
| `Resolve_UsesConfiguredValueFirst` | 调用方传入优先于环境变量 |
| `Resolve_ReturnsEmpty_WhenNothingConfigured` | 都没有时返回空串，不偷偷用默认值 |
| `MissingKeyError_TellsUserWhereToPutIt` | 断言**产品里那个真实的提示字符串**（不是测试自己拼一份） |

**守卫有牙（探针反证）**：临时加一个 `GuardProbe.cs` 内含 `$2a$10$deadbeef` →

```
源码里仍有 CurseForge API Key 字面量（第三方 Key 不得进分发程序）：GuardProbe.cs
失败!  - 失败: 1，通过: 0        ← 红了
```

删除探针后同一用例恢复绿。**这一步是刻意做的：只写"它会红"不算证据。**
