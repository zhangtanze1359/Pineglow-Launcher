# Gitee 清单被源码镜像覆盖 · 事故与修复 · 2026-11-24

## 事故

**v1.0.7 的更新清单被我自己做的两个修复互相打架弄丢了一次。**

### 时间线

| 时间 (+08) | 事件 |
| --- | --- |
| 13:58 | 手工上传 v1.0.7 附件到 Gitee |
| 14:00 | 手工通过 contents API 把 `update.json` 更新到 **1.0.7** |
| 14:01 | **`mirror-gitee.yml` 自动触发**，整分支 force push，用仓库里的 **1.0.6** 覆盖了 Gitee |
| 之后就处于 1.0.6 | 直到本次修复 |

### 根因：两个修复互相打架

| 提交 | 意图 | 实际效果 |
| --- | --- | --- |
| `16939f8` | 把 `update.json`（1.0.6）纳入仓库，防止同步时丢失 | 让仓库里有一份**过时的清单** |
| `1a7baae` | 新增 `mirror-gitee.yml`，每次 main push 整分支 force push | **用那份过时清单覆盖 Gitee** |

**真正的错误在于**：`update.json` 是**发布产物**，不是源码。它**不该进版本控制**。

## 用户影响（诚实评估）

| 用户 | 影响 |
| --- | --- |
| v1.0.6 及更早 | **不会收到 v1.0.7 的升级提示**（`latest=1.0.6` = `current`） |
| v1.0.7 | 无影响（已是最新） |

**不是全断，但升不了级**——新版本发不出去。

## 修复（两步）

### 第一步：`update.json` 移出版本控制

- `git rm --cached update.json`
- 加入 `.gitignore`（含原因注释）

### 第二步：镜像前后备份/恢复

新增 `scripts/mirror-gitee-manifest.ps1`：

| 模式 | 行为 |
| --- | --- |
| `backup` | 推送前从 Gitee 读出 `update.json` 内容与 sha，存到临时文件 |
| `restore` | 推送后写回 |

**第三次修复才正确**：`restore` 最初用 `PUT + 旧 sha`，实测 **HTTP 404**——
force push 已把文件删除，PUT 找不到目标。改为**先探测是否仍存在**，不存在则用 **POST 重建**。

## 验证

| 项 | 结果 |
| --- | --- |
| backup 模式 | ✅ 读出 3963 字节，version=1.0.7，sha `cc986cb6` |
| restore（文件存在） | ✅ PUT + sha，HTTP 200 |
| **restore（文件已删）** | ✅ **POST 重建，HTTP 201** |
| CI 实测（run `45353789723`） | ✅ 日志：`已备份 1.0.7` → `目标已被推送删除，用 POST 重建` → `已恢复 HTTP 201` |
| Gitee 主源末态 | ✅ `version=1.0.7`、`sha256=19f4de7c…` |

## 现状

| 仓库 | SHA |
| --- | --- |
| 本地 / GitHub `main` | `6eef1a9` |
| Gitee `master` | `68cec6c`（`mirror: restore update.json`，恢复脚本产生） |

**Gitee 多一个提交是预期行为**：恢复清单必然在 Gitee 产生新提交。
下次镜像会再推 `main` 覆盖它，然后再次恢复——**循环但无害**（清单内容不变）。

## 遗留

1. **`update.json` 现在只存在于 Gitee（通过 API 管理）**，GitHub 仓库里没有。
   这符合"发布产物"的定位，但意味着**清单的备份依赖于 Gitee 本身**。
   > 建议：每次 `release.yml` 发布后，把当时的清单另存一份到 `docs/evidence/<版本>/`，
   > 作为可追溯的记录（**不要**放进会被镜像覆盖的位置）。

2. **循环的副作用未完全评估**：每次 main push 都会让 Gitee 多一个 `restore update.json` 提交。
   长期会累积。若在意，可改为"仅在清单内容变化时才提交"。

3. **`release.yml` 的 token 转义 bug 仍未在 CI 验证**（`c005495` 修复）。
   下次发版才知道对不对。

## 这一轮暴露的模式

我在同一天里做了两个"防丢失"的修复（把清单纳入仓库、加自动镜像），
**它们各自合理，组合起来互相破坏**。

**教训**：修一个地方时，要检查它和**另一个修复**的交互。
