## 三、必须如实记录的一件事：C# 首次全量出现 1 个 flake

**这是本轮唯一一次红色，不隐瞒。**

第一次 `dotnet test`（退出码 **1**）失败：

```
[xUnit.net 00:00:00.50]  Pineglow.Launcher.Tests.LoggingAndPathsTests.LauncherLog_ManyConcurrentWrites_ProduceCompleteLines [FAIL]
Assert.Equal() Failure: Values differ
Expected: 200
Actual:   203
失败!  - 失败: 1，通过: 1378，已跳过: 0，总计: 1379，持续时间: 58 s
```

完整原始输出保留在 `dotnet-test-first-run-FLAKE.txt`（未删除、未编辑）。

### 定性

**偶发（flake），不是本轮改动引入的确定性缺陷。** 依据：

1. 本轮改动**全部在前端**（`ui/` 下 16 个文件 + 1 个新文件），`git status` 里
   `dev/PineglowLauncher.Tests/` 与 `dev/PineglowLauncher/` 均无改动，不可能改变该测试的行为。
2. 该测试单独跑 **3/3 通过**。
3. 全量重跑 **3/3 通过**（首次复现那 1 次之后再跑三次全量全部 1379/1379）。

### 机制（可复核）

`LauncherLog` 是**静态全局单例**（`dev/PineglowLauncher/Pineglow.Launcher.Services/LauncherLog.cs`），
`_writer`／`_dir`／`_file` 都是 `static`。仓库**没有** `xunit.runner.json`，也没有
`[CollectionBehavior]`／`DisableTestParallelization` 配置，因此 xUnit 默认让各测试类**并行**。

`LauncherLog_ManyConcurrentWrites_ProduceCompleteLines`（`LoggingAndPathsTests.cs:167`）在
自己的临时目录里 `Init(dir)` 后写 200 行，再读回并断言**恰好 200 行**。只要在它持有
`LauncherLog` 静态状态的这段时间里，**别的测试类**里有产品代码调用 `LauncherLog.Info/Warn/Error`
（例如网络重试、更新检查、诊断日志），那些行就会追加进同一个当前日志文件——203 就是这么来的
（多出的 3 行不是 200 条并发写产生的，是外部注入）。

这属于**测试自身依赖全局静态状态**的既有脆弱点，与本轮拆分无关。

### 本轮的处理边界

按 AGENTS.md「执行者 ≠ 裁判」与 CC 角色边界（禁止触碰 C# 产品逻辑），我**没有**去改
`LauncherLog.cs` 或这条断言。把它记进证据包，留给编排方/Codex 决定是否单独立项
（可选方向：给该断言加 `[Collection]` 串行化、或断言改为"至少 200 行且 200 条 `line-` 前缀齐全"
——但那是改断言，必须由裁判方拍板，不由执行者自行放宽）。

## 四、守卫断言的有效性（变异验证）

「新加的守卫必须真的能咬住」——不靠自述，靠注入变异看它是否变红。
`ui-script-order.test.cjs` ⑤ 组三条断言，逐条做过变异：

| 变异 | 操作 | 结果 |
|---|---|---|
| MUT-1 | 从 `ui-script-order.cjs` 的 `SCRIPT_ORDER` 删掉 `js/downloads.js` | **变红**：3 条失败（清单↔HTML 一致性、js/ 反向登记、⑤-①） |
| MUT-2 | 从 `ui/index.html` 删掉 `<script src="js/downloads.js">` | **变红**：2 条失败（清单↔HTML 一致性、⑤-②） |
| MUT-3 | 把 `renderDownloads()` 掏空为 `return ''`（`__wire` 调用保留） | **变红**：1 条失败（⑤-③渲染分支） |
| MUT-3b | 把 `bindDownloads(el)` 掏空（`__wire` 调用保留） | **变红**：1 条失败（⑤-③绑定分支） |

全部变异在**同一次 shell 调用内**用备份恢复，恢复后基线 8/8 绿。

### MUT-3 曾经**没有**咬住——已修复，如实记录

初版 ⑤-③ 只断言"launcher.js 里出现过 `SG.downloads`"，而 `SG.downloads.__wire(...)` 那一行
本身就满足它。于是"脚本加载了、也'引用了'，但视图接线被掏空"这种**假接线**，守卫依然全绿——
这正是本项目反复返工过四次的「不把跳过写成通过」同型缺陷，且是**我自己引入的**。

已改为要求**渲染入口与绑定入口真的委托过去**：

```js
const delegatesRender = /[\\s{;]name:\\s*\\{[^}]*SG\\.name/.test(launcherSrc)          // VIEWS 表内联
  || /render:.*SG\\.name\\.render/.test(launcherSrc)                                   // 内联箭头
  || /function renderName\\(\\)\\s*\\{\\s*return SG\\.name/.test(launcherSrc);          // 具名薄委托
const delegatesBind   = /SG\\.name\\.bind/.test(launcherSrc)
  || /function bindName\\(el\\)\\s*\\{\\s*return SG\\.name/.test(launcherSrc);
```

改后 MUT-3 与 MUT-3b 均变红（见上表），恢复后 8/8 绿。

## 五、拆出时发现的真实漂移（已修）

`ui/tests/helpers/live-launcher.cjs` 原本硬编码加载清单
`['i18n.js','api.js','news.js','launcher.js']`。拆 `news.js` 时已漂移过一次，拆 `downloads.js`
时**又漂一次**，症状都是：

```
TypeError: Cannot read properties of undefined (reading '__wire')
```

——14 个测试失败，看起来像"某个测试的环境问题"，实际是加载清单漂移。

已改为从 `SCRIPT_ORDER`（单一来源）派生，同时**保留** `PINEGLOW_UI_TEST_SOURCE_DIR`
指向旧 HEAD `ui/js` 副本的复验能力（按 `path.basename(entry)` 解析，不用绝对路径）。
