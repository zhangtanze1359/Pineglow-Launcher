## 三、升级链路（真机，v1.0.3 → 1.0.4）

用 **v1.0.3 的官方单文件 exe**（从 `v1.0.3` Release 下载）以便携模式启动，页面里调用 `SG.api.checkUpdate()`，原始返回：

```
currentVersion   = 1.0.3
updateAvailable  = true
latestVersion    = 1.0.4
manifestSource   = https://github.com/.../releases/latest/download/manifest.json
downloadUrl      = https://github.com/.../releases/download/v1.0.4/Pineglow-Launcher-win-x64-single-file.exe
usedFallback     = true
notes            = v1.0.4 的更新日志（MCBBS 下线 + 登录文案 + 版本号）
```

`usedFallback=true` 的原因：首选清单源 `gitee.com/ztz1359/.../update.json` 仍 404（历史上就没配），
客户端按设计自动回退到 GitHub Release 的 `manifest.json` —— 这条回退链在 v1.0.3 里本来就存在，本次实测生效。

## 五、已知状态 / 未验证（不隐藏）

1. **Gitee 中转未配置**：CI 日志明确写「Gitee 附件上传失败：未改写 manifest、未更新固定 update.json；manifest 保持 GitHub 直链」。
   后果：国内用户检查更新与下载走 GitHub，速度取决于网络；**不影响正确性**（清单与资产校验一致）。
   要开国内中转，需要配 `GITEE_TOKEN` 后再打一次 tag（或单独跑 workflow）。
2. **没有真的点「下载并更新」走完替换+重启**：本轮只验到"检查更新返回 1.0.4 + 下载地址正确 + 资产哈希一致"。
   真正的 `Apply update`（下载、替换正在运行的 exe、重启）**未执行**——那需要在一个能关闭自身进程的环境里做，且会动本机安装。
3. **不是干净机器**：冷启动是在本开发机（已装 WebView2 运行时）验的，不是全新 Windows。
4. S5 里两项手测（原版/Fabric/Forge 安装、离线启动）仍未做（与本轮无关，但发布时确实没验）。
