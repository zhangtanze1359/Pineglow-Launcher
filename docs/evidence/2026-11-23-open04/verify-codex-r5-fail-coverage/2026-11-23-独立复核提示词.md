# OPEN-04 文档补齐后的独立复核提示词

请在指定隔离工作树内只读复核补齐提交，并先记录 `Get-Location`、`git rev-parse --show-toplevel`、`git rev-parse HEAD`、`git status --short --untracked-files=all`。请阅读同目录《最小补齐流程》和第 5 轮交接报告。以补齐后的冻结提交为复核对象，记下完整 SHA。

1. 用 `git diff --exit-code 63dadf7 <冻结提交> -- dev/ scripts/test-inventory.txt .github/workflows/build.yml global.json` 与 `git diff --name-only 63dadf7 <冻结提交>` 验证输入。输入未变时，复用第 4 轮归档的 19 份 TRX 与第 5 轮的复算，记录 4567 通过、0 失败、0 跳过，目标 16 次 `applied`、三轮全量的 1502 个唯一测试 ID 一致。输入有变化时按变化决定需复核的项目。
2. 逐条回查台账累计数字、各轮结论和执行证据 README 的时序、失败恢复、API 互斥三条证据。目标用例的成功状态和等待耗时、旧版内容及重启标记必须各自对应源码和原始输出。检查第 5 轮已验明的四处措辞与七项未验证边界是否仍忠实保留。
3. 按台账「未复现但由独立复核明确接受已有覆盖与风险说明」作明确判断，附实际命令、退出码、原始证据、剩余风险和 `FormalPhaseApproval=NOT_GRANTED`。如有失败，精确标明文件和行号。

只在自己的工作树内写复核证据。此任务不授权写主工作区、修改产品或测试、提交、推送、打 tag 或发布。
