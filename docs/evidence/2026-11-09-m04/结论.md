## 1 结论（先给判定）

**失败原因归类：环境缺少依赖（解释器名写死为 Windows 专有名），不是脚本自身逻辑退出，也不是工作流未调用。**

`scripts/tests/goal-validation.test.cjs` 在修复前使用：

```js
const PWSH = process.env.DSH_PWSH || 'powershell.exe';   // 修复前（main 8845574f）
```

GitHub `ubuntu-latest` runner 只提供 PowerShell 7（二进制名 `pwsh`），没有 `powershell.exe`。于是 `spawnSync` 解析不到可执行文件：进程从未启动（`error.code = ENOENT`），`proc.status` 为 `null`。测试内部把 `proc.status` 直接当作退出码返回，上层读到的就是「进程未启动产生 null 退出状态」——与 11-03 诊断记录的现象一致。

修复（合流提交 `91d71ac`，2026-11-07 20:29）：

```js
const PWSH = process.env.DSH_PWSH || (process.platform === 'win32' ? 'powershell.exe' : 'pwsh');
// 并对 spawn 失败显式抛错，不再让 null 静默变成「退出码」：
if (proc.error) throw new Error(`Cannot execute ${PWSH}: ${proc.error.message}`, { cause: proc.error });
```

Windows 侧行为不变（仍是 PowerShell 5.1），未删用例、未改断言、未放宽超时。

### 4.1 失败机理最小复现

`docs/evidence/2026-11-09-m04/repro-null-status.cjs`（只读脚本，不碰产品代码）：

```
[1] missing interpreter -> status     = null
[1] missing interpreter -> error.code = ENOENT
[2] old code on linux  -> powershell.exe
[2] new code on linux  -> pwsh
[2] new code on win32  -> powershell.exe
[3] spawn 失败已显式抛错 -> Cannot execute …: spawnSync … ENOENT
RESULT=PASS   (exit 0)
```

即：把「不存在的解释器」交给 `spawnSync`，得到的正是 `status=null` + `ENOENT`，与失败现象一一对应；修复后的写法在 Windows 上仍解析为 `powershell.exe`。
