# 在线更新通知与版本介绍实施计划

**Goal:** 启动与运行期间自动发现新版，展示版本介绍，继续由用户下载并重启。

**Architecture:** 保留现有更新 API、下载校验和替换恢复链。独立的前端检查调度器负责启动、定时、恢复前台、请求去重和通知去重；界面复用现有对话框。内置清单并行查询并选最高版本，版本介绍从清单和匹配版本的官方 GitHub Release 获取。

**Tech Stack:** 原生 JavaScript、Node test、C#/.NET 10、xUnit、PowerShell、GitHub Actions。

**Spec:** 用户本聊天 2026-10-15 的自动提醒、新版本介绍及尽快修复要求。

## 约束与基线

- SourceRoot: `D:/松光启动器`；HEAD: `39e03f2b673ed342647821ae37d5e6291c028495`；开始时工作区干净。
- EvidenceRoot: `docs/auto-update-2026-10-15/`；测试使用本机假服务或拦截请求，不修改实际用户配置，不下载/替换用户程序。
- 不提交、不推送、不打标签、不发布。旧客户端必须先升级到包含本修复的版本才能自动提示。
- 3 秒后首次检查；每 10 分钟再查；恢复前台超过 1 分钟补查；后台隐藏时不查询；同版每次启动只弹一次。已有业务弹窗不被覆盖。
- 更新介绍按纯文本显示，保留换行，不执行远程 HTML。网络失败静默且后续重试，手动检查仍显示失败原因。

## 实施与验证

1. 扩展 `UpdateManifestFallbackTests.cs`：旧主源+新备用源选新版、并行超时不遮住可用结果、相同版本主源优先、全失败/取消、API 检查与下载选版一致。
2. `UpdateService.cs` 增加并行择新版方法，`LocalApiService.cs` 检查和下载统一调用。读取已知官方仓库匹配版本 Release 的正文，失败保留清单说明。
3. 新建 `ui/js/update-monitor.js` 和聚焦 `ui/tests/update-monitor.test.cjs`：可控时钟验证启动/定时/前台/隐藏/失败恢复/去重/新版本。
4. `index.html` 加载模块，`launcher.js` 在初始化中启动监视并展示提醒条和版本介绍对话框；补充中英翻译和有界滚动样式；手动检查复用同一结果与请求。
5. 增加版本介绍生成脚本，从 `release-notes/<tag>.md` 读取非空介绍；release 工作流把同一说明写入 manifest 和 GitHub Release，Gitee 镜像保留该说明。新增脚本聚焦测试并执行 actionlint。
6. 先保存聚焦 RED，再修复并保存 GREEN；运行已有更新回归、前端回归、Release 构建和真实 Chromium 本机假 API 界面检查。记录证据层级，不声称真实 GitHub 发布或真实替换重启已通过。

## 停止点

本地修复、测试、构建、界面验证与交付报告完成后停止；线上发版另需用户明确授权。
