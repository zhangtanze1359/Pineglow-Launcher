# 新 UI 后续运行时与完整回归闭环方案

此文档记录独立遗留项，不授权提交、发布或修改系统安全设置。UI 集成已实施；后续只处理下面尚未闭环的运行问题。

## 证据与影响

1. `docs/ui-integration-2026-10-15/listener-product-probe.log`、默认 C# 回归和原生启动日志证明：本机 .NET 10.0.9 下带产品依赖的 HttpListener.Start 抛错误 6。相同探针显式使用已安装 10.0.0 后成功。现阶段只能确认运行时/依赖组合差异，不能宣称已查明 .NET 官方缺陷。
2. 自定义 DotNetHostPath 与生成目录内 runtimeconfig 选择 10.0.0 后，完整 C# 回归完成了 507 项，但长期没有结束；停止自有 testhost 后 TRX 标为中止。必须定位剩余活动用例，而非忽略或将部分通过当成全量通过。
3. 同机多个 WebView2 验证窗口参数不一致时发生 0x8007139F；关闭本轮旧窗口后最新构建独立启动成功。不得关闭其他用途不明的用户进程来清场。

## 建议执行顺序

1. 冻结当前 HEAD、tracked diff、新增六个生产/测试/启动文件与最终哈希；保留本轮所有 RED 和中止记录。
2. 在独立运行目录对比最小 HttpListener、仅引用产品程序集、逐组增加依赖三种探针；分别记录 10.0.0 与 10.0.9。确认架构、实际 coreclr 路径、平台版本和加载依赖。优先收集能够区分“平台运行时问题”和“产品依赖初始化问题”的证据。
3. 为完整 C# 回归打开每用例开始/完成日志与有界超时，锁定具体卡住的用例。保持凭据内存后端、portable 输出和隔离 TEMP；不得把夹具失败修成产品默认成功。
4. 选择经验证且仍符合项目支持策略的运行方式；不得仅为了测试变绿把产品永久锁死在旧补丁版本。任何包或运行时升级要单独核对兼容性与项目约束。
5. 逐项重跑有效失败用例，再执行 944 项完整 C# 回归、353 项 Node 回归、资源闭包、最新构建真实 WebView2 十页。测试数量如发生有意义变更，要解释差异。
6. 独立确认正常桌面入口启动真实本地 API；失败时显式错误，生产入口不能显示 mock 账户或模拟成功。再单独验证一个隔离真实游戏的启动/退出会话记录。

## 范围与停止点

先只读研究运行时、依赖、WebView2 初始化及已有测试。需要修复时仅修改已证明必要的启动/运行时兼容路径和对应测试；不要重写新 UI、扩大到全部后端、改真实配置、修改代理/防火墙/TLS 或删除未知文件。所有必要门槛完成后交付证据与精确结论；提交、推送、打包发布和正式放行另需对应授权。
