## 二、B0 的回灌范围结论（已核实）

**三个产品提交带回，证据文档 `f02184d` 不带。**

理由：`f02184d` 是 `release/v1.0.4` 上 S5 的验收包，描述的是那条线上四门槛的结果；`main` 的门槛数字完全不同（1432/489 且待重跑）。把它的结论搬进 `main` 会变成假证据。

### 冲突预判（已在临时 worktree 实测，未留痕）

| 提交 | cherry-pick 结果 |
|---|---|
| `a9de88e`（登录文案） | **干净**，无冲突 |
| `f38b070`（MCBBS） | **3 处冲突**：`LocalApiService.cs`、`ui/js/api.js`、`ui/js/launcher.js` |
| `b88803f`（版本号） | **1 处冲突**：`Pineglow.Launcher.csproj` |

三处冲突的成因都能事先说清，不许"边解边看"：

1. **`LocalApiService.cs`** —— `main` 上这个文件已经**拆成 19 个 partial**（`ArchitectureReviewTests` / `LocalApiServiceSplitTests` 守着）。
   `f38b070` 改的是原单体文件里的 `LoadConfig` / `SaveConfig` / 一处 `downloadSource` 回传，它们在 `main` 上分散到：
   **`LocalApiService.Configuration.cs:177`（LoadConfig）、`:186`（SaveConfig）、`LocalApiService.Instances.cs:48`（回传）**。
   → **不许**为了省事把代码塞回 `LocalApiService.cs`，那是走回头路。在 `Configuration.cs` 里解。

2. **`ui/js/api.js`** —— `main` 上 mock 世界已搬到 `ui/js/api-mock.js`（`acc9498`），`api.js` 只剩 867 行。
   `f38b070` 改的 mock 源列表在 `main` 上位于 **`ui/js/api-mock.js:311`（延迟表）与 `:317`（源列表项）**。
   → 改 `api-mock.js`，不要往 `api.js` 里加回去。

3. **`ui/js/launcher.js`** —— `sourceLabel()` 已搬到 **`ui/js/settings.js:85`**（`launcher.js` 从 249 KB 降到 3101 行）。
   → 改 `settings.js:86` 的 `names` 映射。

4. **`Pineglow.Launcher.csproj`** —— `main` 上还是 1.0.0。目标值是 **1.0.4**（与已发布的 tag 对齐），不是 1.0.3+1。
