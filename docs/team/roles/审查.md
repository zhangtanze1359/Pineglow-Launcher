# 角色 · 审查（`REV`）

> **重跑命令**后独立判定。这条角色存在的唯一理由：执行者不能给自己签字。

## 一、什么时候该它出场

- 任何标了"完成"的任务，要进验收之前
- 发布前（技术门槛 + 发布放行是两个结论，别混）
- 有人报"我验过了"但没有原始输出

## 二、路径边界

| 权限 | 位置 |
|---|---|
| 允许写 | `docs/evidence/<日期>-<轮次>-<审查者>/` 下全部，含 `验收报告.md`、`SHA256SUMS.txt` |
| 只读 | 产品代码、测试、别人的证据目录 |
| 禁止 | 改任何产品代码或测试（发现缺陷只记，不顺手修）；执行本轮的同一批任务；引用执行者日志当自己的证据 |

**硬规则**：`REV` 不得是本轮任何任务的执行者。如果只有一个人，那这一轮就不许签字。

## 三、接单必须产出

`docs/evidence/<日期>-<轮次>/验收报告.md`，必须含这四块：

1. **判定表**：| 检查项 | 判定（可闭环 / 未处置 / 不可复现） | 依据（文件名 + 行号 / 命令） |
2. **原始输出**：每条判定对应一个文件，文件里是**完整命令 + 完整 stdout/stderr + exit code**。分节存，`SHA256SUMS.txt` 保证没被事后改过。
3. **反证**：对关键断言做变异实验（改坏一处看测试会不会红）。只跑绿说明"没红"，不说明"咬得住"。
4. **不通过的原因分类**：
   - 实现错（回 DEV）
   - 验收标准写错（回 ORC）
   - 环境不具备（写清缺什么，不算通过）

## 四、自检

- [ ] **每一条判定我都自己跑过命令**，没有一条是"根据执行者的日志"
- [ ] 数字与 `docs/baseline.md` 对得上，对不上时先怀疑自己跑错目录
- [ ] 仓库里有 `docs/**/*.log` 的，没被我删改
- [ ] 我区分了「技术门槛 PASS」和「发布放行」——技术绿 ≠ 可以发
- [ ] 未验证项写的是"未验证"，不是"应该没问题"
- [ ] 我对关键断言做了至少一条反证

## 五、这个角色踩过的坑

| 坑 | 实际发生的事 | 现在的要求 |
|---|---|---|
| 引用执行者日志 | 早期验收直接复用执行者的截图/输出 | 必须自己重跑，日志存自己的目录 |
| 技术绿当发布批准 | 六门槛全绿但 R5-04/R5-05 未处置，仍写"可以发布" | `FormalPhaseApproval` 默认 `NOT_GRANTED` |
| 没做反证 | 断言被改写成恒真也照样"通过" | 关键断言至少一条变异实验 |
| 数字"大致一致" | 测试数与 `test-inventory.txt` 差几条被放过 | 双向断言，差一条即 FAIL |
| 在主工作区得结论 | 309 条假失败被写进报告 | 只在 `_worktrees/` 跑 |
