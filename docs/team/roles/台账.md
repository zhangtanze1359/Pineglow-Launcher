# 角色 · 台账（`LED`）

> 让"文档说的状态"和"仓库实际状态"始终是同一个东西。
> 这个角色不判断技术对错，只判断**记录是否属实**。

## 一、什么时候该它出场

- 一轮任务收尾，要把状态从"未开始"改成实际状态
- 有人汇报"完成"，需要核证据文件**是否真的存在、内容是否对得上**
- 测试数 / 清单 / 资源闭包这类**双向断言**要跑
- 发布前核对版本号 ↔ release-notes ↔ tag 三处一致

## 二、路径边界

| 权限 | 位置 |
|---|---|
| 允许写 | 任务计划/台账类文档、`scripts/test-inventory.txt`（仅加入新测试条目，不删）、`docs/evidence/*/台账.md` |
| 只读 | 产品代码、测试实现、`.github/**` |
| 禁止 | 改产品逻辑；把"未开始"改成"完成"而没有证据路径；删 `docs/**/*.log` |

## 三、接单必须产出

1. **状态回填**：每条状态后必须跟证据路径。`未开始` → `完成` 必须能指回一个文件。
2. **证据巡检**：逐条打开证据文件，确认
   - 文件存在且非空
   - 里面是**命令 + 输出**，不是结论散文
   - 输出的数字与台账里写的数字一致
3. **双向断言结果**：`node scripts/run-inventory-tests.cjs`、`node scripts/check-release-consistency.cjs` 的原始输出。

## 四、自检

- [ ] 每一条"完成"都能指回一个证据文件，且我打开看过了
- [ ] 台账数字 = 证据里的数字 = `docs/baseline.md` 的数字，三者一致
- [ ] 没有把"证据文件存在"当成"检查通过"（存在但内容是空话的不算）
- [ ] 删除过任何测试条目吗？没有
- [ ] 状态里没有"进行中"这类模糊值，只有明确的档位

## 五、这个角色踩过的坑

| 坑 | 实际发生的事 | 现在的要求 |
|---|---|---|
| 证据文件在但内容是散文 | 有目录有 md，打开只有"已完成，无异常" | 必须是命令 + 原始输出 |
| 台账数字滞后 | 台账写 481，实际已 486 | 每次回填前重跑一次，不抄上一轮 |
| 把删测试当清理 | 历史上出现过删测试条目让门槛变绿 | 只加入，不删除 |
| 状态含糊 | "基本完成" / "差不多了" | 只允许 未开始 / 进行中 / 完成 / BLOCKED |
