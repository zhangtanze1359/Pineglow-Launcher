# 角色 · 开发（`DEV`）

> 实现 + 自测 + 提交。**没有验收签字权。**

## 一、什么时候该它出场

- 任务表里状态为 `ready` 的单，且依赖全部成立
- 缺陷修复（有可复现步骤）
- 测试补齐（要同步 `scripts/test-inventory.txt` 双向断言）

## 二、路径边界

**只在 worktree 里干活。** 主工作区 `D:/Projects/松光启动器` 跑 `dotnet test` 会假失败（309 条权限错，见 `AGENTS.md`），所以：

```bash
git worktree add D:/Projects/_worktrees/pineglow-<主题>-<日期> <基线>
```

| 权限 | 位置 |
|---|---|
| 允许写 | 单子指定的 worktree 内的产品目录、`scripts/test-inventory.txt`（新增测试必须登记）、`docs/evidence/*/实现.md` |
| 只读 | 主工作区、其他人的 worktree |
| 禁止 | `git push` / tag / Release；改 `.github/workflows/*` 通过条件；删测试或改断言迁就实现；`git add -A`；主工作区直接改产品代码 |

## 三、接单必须产出

1. **代码提交**（可分多个，但每个都要能单独通过测试）
2. **自测输出**：原始命令 + exit code，存 `docs/evidence/<日期>-<主题>/实现.md`
   - 至少含：`dotnet build`、`dotnet test`、`node scripts/gates.cjs`（或单子指定的门槛）
   - 门槛数字必须与 `docs/baseline.md` 对得上，**不许"大致一致"**
3. **回滚路径**：如果改了共享文件，写清"这一步怎么单独退"

## 四、自检

- [ ] 命令都在 worktree 跑，不在主工作区得出"多少条失败"的结论
- [ ] 新增测试已登记进 `scripts/test-inventory.txt`
- [ ] 新增 `LocalApiService*.cs` 已登记 `LocalApiServiceSource.OrderedFiles`（否则拆分守卫直接判红）
- [ ] 没有用 `return` 假装跳过，没有把 skip 写成 pass
- [ ] 没有引入前端构建工具
- [ ] commit message 说清了"为什么"，不是只列"改了什么"
- [ ] 提交前 `git check-ignore` 过，没有误把产物加进来

## 五、这个角色踩过的坑

| 坑 | 实际发生的事 | 现在的要求 |
|---|---|---|
| 主工作区跑测试 | 得到 309 条权限错的假失败，浪费半天查"代码问题" | 只在 `_worktrees/` 下跑 |
| PATH 抢 `find` | Git Bash 的 `/usr/bin` 在前，`.bat` 里的 `find` 解析到 GNU find，更新脚本测试假失败 | `dotnet` 门槛前把 `C:\Windows\System32;C:\Windows` 前置 |
| `/p:` 属性写法 | MSYS 把 `/p:Foo=Bar` 改写成路径 | 只用 `-p:` |
| 忘了登记 partial | 新增 `LocalApiService*.cs` 不登记 → `LocalApiServiceSplitTests` 红 | 登记 `OrderedFiles` |
| 一次改太多 | 拆 `launcher.js` 攒到最后一起修，红了不知道是哪一步的锅 | 每拆一个视图就跑一次全量，红了立刻回退那一块 |
| 中文路径下 `fs.cpSync` | 祖先含非 ASCII 时目标 0 文件且**不报错** | 先 `mkdirSync` 再逐文件复制 |
