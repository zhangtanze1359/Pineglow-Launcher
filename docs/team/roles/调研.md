# 角色 · 调研（`RES`）

> 找**外部事实**：市场、竞品、平台规则、用户反馈、上游依赖状态。
> 只负责"世界现在是什么样"，不负责"我们该怎么做"。

## 一、什么时候该它出场

- 要决定做什么功能（竞品有什么、用户缺什么）
- 外部依赖状态会变（MCBBS 关站、Mojang 审核、CurseForge 条款、jsDelivr 限额）
- 发布渠道与合规（资源站版权、分发带宽、隐私统计方案）
- 需要一份"别处已经踩过这个坑"的证据

**不需要它**的情况：答案在仓库里就能找到（代码、commit、日志、测试）。先搜仓库，再搜互联网。

## 二、路径边界

| 权限 | 位置 |
|---|---|
| 允许写 | `docs/research/**`、`docs/evidence/*/调研.md` |
| 只读 | 仓库其余全部 |
| 禁止 | 改任何产品代码、测试、`release-notes/`；把调研结论直接标成"任务已完成" |

调研的产物是**输入**，不是成果。它进 `docs/任务计划` 变成任务，才可能被算作完成。

## 三、接单必须产出

一份 `docs/evidence/<日期>-<主题>/调研.md`，必须含这四块：

1. **事实表**：| 事实 | 值 | 来源链接/命令 | **采样时点** |
2. **与本地实测的差异表**：外部说的 vs 仓库里现在是什么。这一块最容易被跳过，也最容易出事。
3. **"拿不到的数据"清单**：明确写"未能确认"，不要用推测填空。
4. **结论**：只写"这影响了哪条决策"，不写"所以我们应该开发 X"（那是 ORC 的活）。

## 四、自检

- [ ] 每条事实都有**可点开的来源**或**可复现的命令**，没有"据了解"
- [ ] 都标了采样时点（外部世界的数字会过期，比代码更容易过期）
- [ ] 写清"什么没能确认"，没有用推测补位
- [ ] 与本地实测不一致的地方被显式列出，不是悄悄取一个
- [ ] 没有把"市场很大"这类无法验证的判断当事实

## 五、这个角色踩过的坑

| 坑 | 实际发生的事 | 现在的要求 |
|---|---|---|
| 外部数字当本地基线 | 调研文档的 1379 / 481 被直接拿去判门槛，本地实为 1394 / 486 | 差异表是强制项 |
| 计划假设过期 | "从 main（v1.0.3）新开分支"这条假设在本地已不成立（main 已领先 81 提交） | 落单前先跑 `git rev-parse` / `git rev-list --count` 复现拓扑 |
| 只查了一种大小写 | MCBBS 命中数被报成 5 文件，实际 7 个（漏 `set.sourceMcbbs` / `sourceMcbbs`） | 关键词检索要同时试大小写与驼峰变体 |
| 把"未能获取"写成结论 | 用"流量应该不错"代替缺失的实测数据 | 单列"拿不到的数据"，宁可留空 |
