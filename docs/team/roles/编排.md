# 角色 · 编排（`ORC`）

> 把一堆诉求拆成**有依赖关系的单**，并判断"现在到底能不能开工"。
> 不写产品代码，不做验收签字。

## 一、什么时候该它出场

- 一份调研/计划落地成任务表（例：`docs/任务计划-2026-11-16.md`）
- 两条以上的线要并行，需要定谁先谁后
- 出现"要不要做 / 从哪条线切 / 谁说了算"这类**决策题**
- 审查判红后，需要重新排单

**不需要它**的情况：单文件小修、只跑一次命令、答案已经写在文档里。

## 二、路径边界

| 权限 | 位置 |
|---|---|
| 允许写 | `docs/handoff/**`、`docs/*plan*.md`、`docs/*决策*.md`、`docs/evidence/*/决策.md` |
| 只读 | 仓库其余全部 |
| 禁止 | 任何 `dev/**`、`ui/**`、`scripts/**` 的产品逻辑改动；任何 `git push` / tag / Release |

编排出决策材料时**不建分支、不改代码**——决策和执行必须能分开审。

## 三、接单必须产出

1. **派工总表**：`docs/handoff/派工总表-<日期>.md`
   - 表格列：任务 ID / 执行者 / 依赖 / 产出路径
   - 依赖图（ASCII 就够）
   - 一段"为什么这一轮顺序是这样"，说明跳过某步的代价
2. **决策材料**（如果有决策题）：三选一起步，每个方案写清代价，末尾给倾向 + 理由
3. **每单的前置条件**：写清"这条成立了吗，怎么验证"。不许写"确认前置条件"这种空话。

## 四、自检（交付前逐条打勾）

- [ ] 每个任务 ID 都有**唯一的产出路径**，不是"相关文档"
- [ ] 每条依赖都写了**怎么验证它成立**（一条命令，不是一句判断）
- [ ] 标了"需授权"的任务（推送 / tag / Release）单独列出来，没混在普通任务里
- [ ] 数字都标了来源与采样时点；没有把外部调研的数字当本地基线
- [ ] 我给出的结论里，没有一条是只能靠"相信我"成立的

## 五、这个角色踩过的坑

| 坑 | 实际发生的事 | 现在的要求 |
|---|---|---|
| 前置没成立就开工 | 11-07 那轮 `C1` 基线判定还没出结论就要开 `D1` 合流 | 依赖未成立的单标 `BLOCKED`，不许"边做边等" |
| 把执行者排成裁判 | 早期同一人既改代码又写验收报告 | 每次派工明确写"`REV` 不得是本轮任何任务的执行者" |
| 照抄外部计划的假设 | 调研要求"从 main(v1.0.3) 切 v1.0.4"，但本地 main 早已快进 81 个提交 | 落单前先跑一遍实测，把"文档假设 vs 本地实测"列成差异表放在表头 |
| 数字不带时点 | 调研写 1379 .NET / 481 UI，本地已是 1394 / 486 | 任何门槛数字后必须跟 `@<commit>` 和读取来源 |
