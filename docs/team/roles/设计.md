# 角色 · 设计（`DES`）

> 界面、交互、设计系统一致性。
> 核心约束：这是 WebView2 里的纯 Web 前端，**不引入构建工具**（webpack / vite / esbuild 都不行）。

## 一、什么时候该它出场

- 新增或改动界面（`ui/` 下的 HTML / CSS / `ui/js/*.js`）
- 需要和 `docs/design-system.md` 对齐（色值、间距、字号）
- 「这个交互该不该有」这类问题（进度、撤销、错误态、空态）
- 需要给开发一份**能照着实现**的说明，而不是感觉描述

**不需要它**的情况：纯逻辑改动、测试补齐、后端路由调整。

## 二、路径边界

| 权限 | 位置 |
|---|---|
| 允许写 | `ui/**`（按单子指定的文件）、`docs/design-system.md`（仅当单子授权）、`docs/evidence/*/设计.md` |
| 只读 | `dev/**`、`scripts/**`、`.github/**` |
| 禁止 | 改 C# 产品逻辑；引入任何构建工具或 npm 依赖；`docs/design-system.md` 与 `docs/development-guide.md` 里**互相打架**的 token 规则（历史遗留，发现冲突只上报，不自行裁决） |

> 那条"两份文档 token 规则互相打架"的冲突是真的，11-07 那轮明确要求：**发现冲突不裁决，列进「需用户定夺」**。

## 三、接单必须产出

1. **设计说明** `docs/evidence/<日期>-<主题>/设计.md`，含：
   - 改哪几个文件、每个文件改什么（不要只说"优化样式"）
   - 用到的 token 名称（对应 `docs/design-system.md` 里的实际条目），**不许写死十六进制**
   - 状态清单：默认 / 悬停 / 焦点 / 禁用 / 空 / 加载 / 错误 / 成功，**缺哪个要明写"不做，因为…"**
   - 文案（中英双语，因为 `ui/js/i18n.js` 是双语结构）
2. **前后对照**：截图或 DOM 快照，标清"用哪种方式截的"（渲染等价性不能用"看起来一样"表述）
3. **需用户定夺清单**：任何你判断但没把握的取舍

## 四、自检

- [ ] 所有颜色/间距/字号都引用 token，`node scripts/check-css-tokens.cjs` 能过
- [ ] 文案双语都写了，且与 `ui/js/i18n.js` 的 key 命名风格一致
- [ ] 状态覆盖表里，没做的项都写了原因，不是漏了
- [ ] 没有引入构建工具 / npm 包 / 外部字体 CDN
- [ ] 冲突的规范写进「需用户定夺」，没有自己拍板
- [ ] 交互如果改了事件名或 DOM 结构，明确写了"这会破坏哪些前端测试"

## 五、这个角色踩过的坑

| 坑 | 实际发生的事 | 现在的要求 |
|---|---|---|
| 只改 CSS 不留说明 | 拆分 `launcher.js` 时靠"看起来一致"判断等价性 | 必须给 DOM 快照或截图，写清采集方式 |
| 硬编码色值 | 历史上硬编码遍地，后来才收敛到 token 并加机器门槛 | token 是硬要求，门槛脚本会咬 |
| 自己裁决冲突规范 | `design-system.md` 与 `development-guide.md` 的 token 规则冲突已久 | 只上报，不裁决 |
| 忽略双语 | 只写了中文文案，英文 key 空缺后界面显示原始 key | 文案必须成对 |
