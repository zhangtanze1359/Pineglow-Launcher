## 一、审计发现的两处真实不一致（已修）

### 1. MR10 的状态词非法

计划 §8 明确规定状态词**只能**用七个固定词之一：
`未授权 / 已授权待执行 / 执行中 / 证据就绪 / 独立复验通过 / 暂不放行 / 用户已批准`。

而我在上一轮把 MR10 写成了 **`判定：无需实现（附证据）`** —— **不在允许集合内**。
已改为 `**证据就绪**（**判定：无需实现**；run …）`：状态词合法，"无需实现"作为说明保留。

> 这类问题很隐蔽：内容是对的，但**状态词是机器可读的契约**，写歪了会让任何按状态过滤的工具/人都读错。

### 2. W2/W3 没有引用证据目录

W1/W2/W3 共用同一个合并 run 目录 `W1-W3-route-closure/20261002-182304Z`，
但台账里 W1 只写了裸 run-id、**W2/W3 什么都没写**。复验方按台账去找 W2/W3 的证据会扑空。

已把三行都改成引用**证据目录**（而非裸 run-id），并注明三者同源。

## 四、审计脚本自身的两个已知限制（如实说明）

1. **用前缀匹配识别"这个 run 目录属于哪个包"**：因此里程碑级的 run 目录必须以某个已声称的包开头命名
   （本审计目录用 `MR00-…` 才不会被判成孤儿），或在脚本的 `claimed` 列表里显式登记
   （`MG1/MG2/MG3` 就是显式登记的）。这是**命名约定**，不是自动推断。
2. **只检查"是否可定位"，不检查证据内容**：它不会验证 `manifest.json` 里的数字是否与日志一致——
   那是各里程碑复验脚本（`verify-mg1/mg2/mg3.ps1`）与人工复验的职责。
