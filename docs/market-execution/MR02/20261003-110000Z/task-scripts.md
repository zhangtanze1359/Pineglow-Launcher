# MR02 · 统一任务脚本（4 个任务 + 计时 + 卡点 + 结果表）

> **使用前提**：需用户授权与一个**合成实例副本**。**绝不**在受访者的真实存档上操作。
> 本文件是**空脚本**，不含任何已执行的记录。

---

## 〇、统一前置（每个受访者都相同）

| 项 | 取值 |
|---|---|
| 环境 | 冻结的测试机 + 冻结的启动器候选版本（记录 SHA） |
| 数据 | **合成实例副本**：预置整合包 + 预置崩溃场景；受访者的真实实例只在他明确同意后另行观察 |
| 记录方式 | **默认手工/本地**：纸笔或本地表格；**不接远程遥测**、不自动上传（卡片明确要求） |
| 允许帮助 | 只允许"复述任务"；**不提示操作位置**。受访者主动求助时记 `求助次数+1` |
| 终止条件 | 受访者要求停止、或触及真实数据、或超过 15 分钟无进展 |
| 计时口径 | 从"任务说明读完"到"成功判据达成"或"放弃" |

---

## 任务 1：把一份**已存在**的实例接进启动器

**为什么这样设计**：MR13（Prism/HMCL/PCL 实例迁移）是**条件包、未实现**。
本任务观察的是"用户**现在**怎么把已有实例接进来"，**不是**测试迁移功能。

| 项 | 内容 |
|---|---|
| 任务说明（原话） | "这里有一份已经装好的整合包目录。请让启动器能启动它。" |
| 成功判据 | 启动器里出现该实例，并能启动到主菜单 |
| 计时点 | T1 开始 → T2 找到入口 → T3 成功启动（或放弃） |
| 观察重点 | 是否去找"导入/添加"，是否尝试拖拽，是否误以为要重新下载 |
| 卡点字段 | 停在哪一步、停了多久、说了什么 |

---

## 任务 2：首次安装整合包并进入主菜单

| 项 | 内容 |
|---|---|
| 任务说明 | "请用这个 `.mrpack` 文件装好并进入游戏主菜单。" |
| 成功判据 | 游戏主菜单出现 |
| 计时点 | T1 开始 → T2 选择文件 → T3 下载开始 → T4 下载结束 → T5 主菜单 |
| 观察重点 | 下载慢/失败时的反应；是否知道要等；失败后是否重试；是否理解"缺前置 Mod"的提示 |
| 记录 | 下载耗时、失败次数、失败时的原文提示、受访者的解读 |
| 卡点字段 | 停在哪一步、停了多久、是否求助 |

> **注意**：MR11 的真实端到端导入**尚未验证**。若候选版本在此任务失败，**先记为产品缺陷**，
> 不要当成用户能力问题。

## 任务 3：恢复一次被删掉的 Mod

| 项 | 内容 |
|---|---|
| 任务说明（先制造场景） | 先让受访者删掉一个 Mod（观察他删的方式）；然后说："现在请把它恢复回来。" |
| 成功判据 | Mod 回到启用状态且游戏能启动 |
| 计时点 | T1 删除完成 → T2 发现要恢复 → T3 找到恢复入口 → T4 恢复成功（或放弃） |
| 观察重点 | 是否知道有恢复区；是否尝试重新下载；是否去翻回收站/备份 |
| 记录 | 他第一反应是什么（原话）、花了多久、是否找到入口 |
| 卡点字段 | 停在哪一步、停了多久、是否求助 |

> 这条直接验证 README 的 **H6**（误删用户是否会找恢复入口）。

## 任务 4：定位一个**预置**崩溃

| 项 | 内容 |
|---|---|
| 任务说明 | "这个实例一启动就崩。请找出是哪个 Mod 引起的。" |
| 成功判据 | 指出正确的 Mod（预置场景的唯一答案） |
| 计时点 | T1 开始 → T2 第一次尝试 → T3 使用二分定位（若使用）→ T4 给出答案（或放弃） |
| 观察重点 | 是否直接翻日志；是否使用二分定位；是否理解"测试轮次"的含义；是否被"无效轮次"提示挡住 |
| 记录 | 答案是否正确、用了多久、轮次数、是否中途放弃 |
| 卡点字段 | 停在哪一步、停了多久、是否求助 |

> 这条验证 **H5**（新手卡点在下载而非日志）与 MR06/MR07 的可用性。

## 计算口径（**先冻结再算**，避免事后挑数）

- 完成率 = 成功人数 / **实际参与人数**（分母必须写明，含中途退出者）
- 耗时：报 **中位数与最大值**，不只报平均（人数少时平均无意义）
- 卡点 Top3：按"停留秒数"排序，不按主观印象
- **不把 10 人样本写成总体比例**（计划 §10 明确禁止）
