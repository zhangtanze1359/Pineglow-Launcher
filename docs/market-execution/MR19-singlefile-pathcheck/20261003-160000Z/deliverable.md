# MR19 补测之二 · 单文件 exe 是否受**构建路径**影响

- **run-id**：`20261003-160000Z`
- **性质**：**关掉上一轮自己点名的限制**（"跨路径未测——单文件自包含的经典风险正是嵌入路径"）
- **依据**：`MR19-singlefile-reproducibility/20261003-150000Z/deliverable.md` §四
- **最终状态**：**证据就绪；结果为否定性** —— 跨路径**不可复现**，因此 MR19 的可复现性表述**必须收窄**

---

## 一、结论（这是本轮最重要的产出）

> **同一份源码，在三个不同长度的路径下各发布一次，得到三个不同的 exe SHA。**
> **路径（或其它与路径相关的因素）确实被嵌入了。单文件 exe 的可复现性只在"同一路径"下成立。**

| 构建路径 | 路径长度 | exe 大小 | exe SHA256 |
|---|---|---|---|
| `D:\松光启动器`（就地） | 8 | 89,490,941 | `C99101C8672D7861B6FEF2F29E20F144350771DD9E92F1ABB4DD8987BBA0EC13` |
| `%TEMP%\pgA`（快照-短） | 45 | 89,490,941 | `3AFE016BBB80B5A686056DAD95A04A4BAE4B4EE7ED4859C3D2213300163B62F5` |
| `%TEMP%\pg-long-path-check-0123…`（快照-长） | 93 | 89,490,941 | `F1C10F08670C7D0FC9FAE0C4A612F1E49450F021FE7FD20507FC2474B92DA002` |

**大小完全相同**（89,490,941 bytes），但内容不同：
- 就地 vs 短路径：不同字节 **1,691 / 89,490,941（0.0019%）**，首个不同偏移 **428（0x1AC）**
- 就地 vs 长路径：不同字节 **1,725 / 89,490,941（0.0019%）**，首个不同偏移 **428（0x1AC）**

---

## 二、这个结论**没有被混淆**（决定性对比）

一开始我差点犯一个错：直接比较两个快照的全部文件时，发现 **14 个同名文件内容不同 + 各有一个独有文件**。
如果就此宣称"只有路径不同"，那是**错的** —— 必须先弄清那些差异是什么。

核查结果：

| 项 | 结果 |
|---|---|
| 那 14 个内容不同的文件 | **全部**位于 `bin/` 或 `obj/` 下（构建中间产物，本来就嵌路径） |
| 各有一个独有文件 | `obj/…/PublishOutputs.<hash>.txt` —— **文件名本身就带路径哈希**，也是中间产物 |
| **排除 `bin/obj` 后** | 两个快照各有 **256 个源码输入**；仅一侧有的 = **0**；内容不同的 = **0** |
| 两个快照的"源码输入清单+哈希"整体 | **完全相同**（清单文件 SHA 均为 `4B73958C1D7D3BAF0E0D7767D8D12D20116E875C4DE2C31CA036BAA5B7FDDE12`） |

**所以：两个快照的源码输入逐字节相同，唯一差异就是路径。** 结论成立。

（顺带确认了另一件事：`obj/` 与 `bin/` 里本来就嵌路径 —— 这是**预期**行为，不是缺陷。）

---

## 三、同路径的稳定性被**再次复现**

本轮的"就地"发布 SHA `C99101C8…` 与**上一轮**（run `20261003-150000Z`）两次发布的 SHA **完全相同**，
而上一轮的产物文件至今仍在临时目录里、哈希未变。

即：**同一路径下，跨轮次（相隔约 10 分钟、独立进程）依然逐字节一致** —— 这加强了"同路径可复现"这一半结论。

## 四、机制**未确定**（不推测）

差异出现在偏移 `0x1AC`（很靠前，属 PE 头部/早期区域），但**具体是哪个字段**本包**没有确定**。
可能的候选（**仅列为后续排查方向，本包未验证任何一条**）：

1. PE 头部的 `TimeDateStamp` / `CheckSum`；
2. .NET 单文件 **bundle 清单**（内含各嵌入文件的偏移/大小，或原始路径）；
3. apphost / 原生段里嵌入的构建路径或路径长度派生值。

**要确定它需要单独一次调查**（例如：用相同长度但不同内容的路径再发一次，看是否仍不同 ——
若"同长度不同内容"也导致不同，则更像"路径字符串被嵌入"；若只有长度不同才不同，则更像"长度/对齐派生"）。
**本包没有做这个实验**，所以报告里不写任何机制结论。

## 五、对 MR19 结论的影响（**必须收窄**）

| 表述 | 是否可用 |
|---|---|
| "托管程序集跨强制全量重建逐字节可复现" | ✅ 可用（MR19 原始实测） |
| "单文件自包含 exe **在同一路径下**逐字节可复现" | ✅ 可用（run 150000Z + 本轮就地复现） |
| "单文件自包含 exe **可复现**"（不加限定） | ❌ **不可用** —— 本轮实测跨路径不同 |
| "可复现构建（全链/跨环境）" | ❌ **不可用** |
| "**跨路径不可复现**（实测）" | ✅ **应当写上** —— 这是本轮新增的事实 |

**对 CI/发布流程的含义**（本包**不实施**任何改动，只陈述事实）：
若将来需要"给定源码 → 给定 exe 哈希"的可核对发布，**必须在固定路径下构建**；
否则同一源码在不同工作目录会产出不同字节（虽然行为应当一致）。

## 九、补记（第 28 轮）：判别实验完成 —— 机制方向已定，并**修正**本报告 §四 的一处归因

本报告 §四 把机制列为未定，并写明下一步是"用相同长度但不同内容的路径再发一次"。
第 28 轮做了这个判别实验（`MR19-singlefile-pathlen-discriminator/20261003-170000Z`）：

**① 路径字符串被逐字嵌入产物（决定性）**：在 exe 的 `0xCEEB0D` 处能直接读到
`…\pineglow-pathlen-<guid>\pgA`（P2 则是同偏移处的 `…\pgB`）。
**同长度、只差一个字母 → 产物不同**（95 字符：`199D6FBA…` vs `D23A45C6…`）。
因此"只有长度影响产物"的假设**被推翻**。

**② `0x1AC` 不是长度效应（修正本报告 §四）**：本轮 95 vs 95 与 95 vs 102 两组对比，
首个差异**都在 `0x9AD088`**，而 `0x1A0..0x1C0` 区间**完全相同**。
所以 `0x1AC` 只出现在**本报告那组"D: 盘就地 vs C: 盘临时目录"**的对比里 ——
候选是**盘符/根路径差异**，**原因仍未确定**（本报告当时只打印了"就地 vs 各快照"，
没打印两个 C: 快照之间的对比，所以无法区分这一点）。

**下一步**（未做）：在 D: 盘建一个与 C: 快照**等长**的路径再对比；若 `0x1AC` 仍不同则为盘符/根效应。
