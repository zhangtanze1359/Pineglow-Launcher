## 一、**先测行为，再断言不变量**（不预设结论）

第 41 轮实测过一个 Windows 细节：**用 `FileShare.None` 打开的文件仍然可以被重命名**。
因此"锁住目标文件"**不一定**让替换失败（隔离阶段是移动，可能照样成功）。
所以本包不预设"锁住就会失败"，而是断言**无论成功与否都必须成立的不变量**：

1. **不崩**：返回明确的成功，或带**可读 error** 的失败；
2. **旧版本永远可恢复**：要么**原地逐字节不变**，要么**完整进了恢复区** —— 否则就是数据丢失；
3. **不留垃圾**：mods 目录里不出现 `(1)` 副本、`*.tmp`、`*staging*` 残留。

---

## 二、实测结果（三种场景）

| 场景 | 状态码 | 错误信息 | 旧版本位置 | 判定 |
|---|---|---|---|---|
| **① 目标 jar 被独占打开**（`FileShare.None`） | **500** | `The process cannot access the file '…\mods\a.jar' …` | **原地逐字节不变** | ✅ 明确失败、零数据损失 |
| **① 释放锁后重试** | **200** | — | 进恢复区 | ✅ 瞬时占用不留下永久阻塞 |
| **② 侧车被独占打开** | **400** | `[quarantine_failed] 旧文件隔离失败，已回滚：b.jar → restored；b.jar.mcmini.json → failed` | **原地** | ✅ 回滚语义清楚 |
| **③ 目标文件只读** | **200** | — | 进恢复区 | ✅ 只读不影响（Windows 上只读文件仍可移动） |

**结论**：文件被占用/只读时，替换**要么安全成功、要么明确失败并保住旧版本** —— 没有数据丢失、没有垃圾残留 ✓。
