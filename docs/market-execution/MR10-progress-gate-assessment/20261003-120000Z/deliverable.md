## 一、判定结论

> **MR10「真实进度协议」记为"无需实现"。**

理由（三条，逐条有证据）：

1. **本地模式的等待量级不需要进度反馈**：端到端 **p50 327 ms / p95 357 ms**，
   而且其中 **311 ms（95%）根本不是诊断工作**，而是一次 Java 查找（见 §四）。
   真正的诊断三阶段合计约 **15 ms**。
2. **AI 路径已经有诚实的等待与取消状态**：等待时界面显示「正在分析崩溃日志…」+ **取消按钮**，
   **没有虚假百分比**（有契约测试锁定）；等待上界来自客户端超时 **60 s**（不是前端计时器推断）。
3. **服务端没有可供推进的"真实阶段事件"**：AI 调用是**一次阻塞式 HTTP 请求**，
   唯一可观测的事件是"已发出"——而 MR08 已经记录了它（`aiDispatch.sentAtUtc`）。
   若为此新增轮询协议，最多能报 2 个事件（发送前/收到后），**收益极低**，
   却要付出新端点、单调序列、过期忽略、重启后终态等一整套成本。

**并且**：本仓库**没有任何用户证据**表明存在等待体验问题（MR02 是准备包，实际访谈 0 人）。
按计划纪律，**不能在没有样本的情况下声称存在体验问题**。

## 二、测量证据（可复跑）

```powershell
$env:MR10_ITERATIONS='10'; $env:MR10_EVIDENCE_DIR='<证据目录>\raw'
dotnet test --filter "FullyQualifiedName~DiagnoseProgressGateTests"
```

场景：合成实例 **60 个 Mod + 1.2 MB 日志**（贴近真实整合包量级），本地模式（**不发外网**）。

| 指标 | p50 | p95 | 占端到端 |
|---|---|---|---|
| `diagnose.local.endToEnd`（`POST /diagnose` 往返） | **327.303 ms** | **357.388 ms** | 100% |
| `diagnose.stage.javaFind`（`JavaLocator.FindAsync`） | **311.535 ms** | 324.710 ms | **95.2%** |
| `diagnose.stage.sanitize`（长日志脱敏 + 证据挑选） | 11.822 ms | 16.116 ms | 3.6% |
| `diagnose.stage.modScan`（枚举 60 个 Mod） | 1.447 ms | 2.471 ms | 0.4% |
| `diagnose.stage.ruleEngine`（读 1.2 MB 日志跑规则） | 1.300 ms | 1.972 ms | 0.4% |

**读法**：即使把三阶段全部优化到 0，本地诊断也只从 327 ms 降到 ~316 ms。
**本地模式不存在"需要进度条"的等待**。

## 四、附带发现：一个比 MR21 候选修复**大一个数量级**的真实瓶颈

诊断 handler 为了让报告里有 `javaVersion`，在**每次**诊断时都会：

```csharp
JavaInfo javaInstallation = await JavaLocator.FindAsync();   // ← 实测 311 ms
javaVersion = javaInstallation?.VersionText ?? javaInstallation?.Path;
```

**实测 311 ms**（3 次：306.1 / 324.7 / 311.5 ms），占本地诊断端到端的 **95%**。

对照 MR21 的结论：MR21 在它选定的服务层指标里把 `sanitize` 判为最慢（当时 11–30 ms），
候选修复实测 p50 −80%。**但 MR21 没有测诊断端到端**，因此没有看到这 311 ms。
本包如实记录这一差异 —— **MR21 的结论在其范围内成立，但不是这条用户可见路径的主要成本**。

**建议**（本包**不实施**，按计划纪律应走独立子包授权）：
- 把 Java 版本探测的结果**缓存**（按 Java 路径 + mtime 失效），或
- 让诊断**不必**同步等待 Java 探测（`javaVersion` 缺失时报告里写"未知"即可，规则与 AI 都不依赖它），
- 两者都能把本地诊断从 ~327 ms 降到 ~16 ms（**−95%**）。

**变化风险**：缓存会让"用户刚换了 Java"之后的第一次诊断显示旧版本；
按路径+mtime 失效可避免，但需要写缓存失效用例。
